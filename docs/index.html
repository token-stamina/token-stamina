Make your weekly limit last until the reset.

A Claude Code plugin that compares your usage with the time left. When you run ahead, it moves subagents to cheaper models, suggests a compact at the right moment, and keeps a handoff note so you don't lose your place.

    Always on, at any grade: a handoff note saved at the end of each turn and restored after a compact or clear, and a /compact suggestion when the conversation gets long.

    01What it does

    Subagent model

    auto

    When you run ahead of pace, subagents with no model set move to Haiku or Sonnet.

    More

    While the grade is red, a subagent call with no model set goes to Haiku if the task looks simple and to Sonnet otherwise. When several subagents or sessions are running at once, yellow is enough. A call that names a model, is a fork, or looks like review or design work is never changed: at most Claude gets a suggestion. You can change this to suggestions only, or turn it off.

    Handoff note

    auto

    Saves where you were at the end of every turn and brings it back after a compact or clear.

    More

    At the end of each turn it saves the last few requests, commits, edited files and to-dos, and adds them to the new conversation after you compact or clear, including the desktop app's clear. The note is put together from your transcript; no model writes it. After a clear, the last few turns are also shown on screen only, not sent to the model. You can compact early and not have to explain again where you were.

    Compact suggestion

    suggestion

    Suggests /compact right after you finish something in a long conversation.

    More

    Once the conversation is large, Claude is asked to end the task with a /compact suggestion (a card with buttons in the desktop app). If the conversation is much larger than that, it suggests a new session instead. Past a higher size, a short topic check asks Claude to offer a clear when your next request is on a different topic.

    Auto-compact point

    set once

    Setup can move Claude Code's automatic compact earlier, so long sessions re-read less.

    More

    Setup can lower Claude Code's automatic compact point, so a long session doesn't keep re-reading a very large context on every call.

    Grade change

    once

    One short line when the grade changes, in your language. Nothing while it stays the same.

    More

    When the grade changes, Claude gets one short line and tells you, in your language. Nothing is added while the grade stays the same.

    Reports

    on request

    Four commands show usage, estimated savings, fixed costs and running subagents.

    More

    They read your local transcripts and the plugin's own log, print a table and call no model. Savings figures are estimates, not billing.

    It doesn't change your main conversation's model or block requests. It doesn't compact by itself either: Claude Code doesn't let plugins run /compact. It draws its own status row and doesn't touch your status line setting.

    02How the grade works

    The status row shows the usage numbers Claude Code already reports, plus the grade.

    7d 84% · today 5.3% ● · reset Mon 15:00 · ctx 41%
    7d 84%
    weekly limit used, as reported by Claude Code
    today 5.3%
    what you can use per day from now and still make it to the reset
    ●
    grade: green, yellow or red
    reset Mon 15:00
    when the weekly window resets
    ctx 41%
    how full this conversation is

    60% used with a day left is fine. 60% used on day two isn't. So the grade compares usage with time. Green if usage is at or below the share of the window that's gone. Yellow if it's up to 10 points over. Red if it's more than 10 points over, or at 90% or more at any point. The weekly and 5-hour windows are graded separately and you see the worse one.

    03Install

    Requires Claude Code 2.1.308 or later. On an older version, run claude update first. No Node.js needed.

    1In a terminal, add the marketplace:

    claude plugin marketplace add token-stamina/token-stamina

    2Then install the plugin (adding the marketplace alone doesn't install it):

    claude plugin install token-stamina@token-stamina

    3Start a new Claude Code session (sessions already open don't see the plugin). The status row appears after the first response. There's nothing to set up.

    Optional: /token-stamina:setup sets the language of the hints, cleans up the status line entry left by 0.5.x and offers an auto-compact point. It shows every file change first and waits for your yes. To update later, run claude plugin update token-stamina@token-stamina and restart Claude Code.

    Or do steps 1 and 2 inside Claude Code

    Run these one at a time, then start a new session:

    /plugin marketplace add token-stamina/token-stamina
    /plugin install token-stamina@token-stamina

    04Commands

    Each prints a table from files on your machine. None of them calls a model or changes anything.

    /ts-report
    usage by model, main conversation vs subagents. Last 30 days by default, or --since YYYY-MM-DD.
    /ts-savings
    tokens the plugin likely saved. An estimate, not billing. It reads the plugin's own log, so savings before 0.6.0 are not counted the same way.
    /ts-audit
    what loads into every conversation: always-loaded files, plugins, MCP servers and skills, and what you could turn off.
    /ts-fleet
    subagents running now, by model.

    /token-stamina:autocompact picks when Claude Code compacts on its own (300k, 400k, 600k or default). It shows the change and asks first.

    05Usage Advisor

    since 0.6.3 Token Stamina already acts on your pace. The Usage Advisor looks further back: it reads your last 30 days of local session records, shows where the usage goes, and proposes concrete changes to your settings. Nothing is changed until you approve it, one item at a time.

    1. Analyze. Adds up the last 30 days by main session, subagents, cache reads, cache writes and output, and finds the biggest leaks: subagents on an upper-tier model doing implementation work, caches that expired while a subagent waited, returns after a long idle, and sessions still on an old model.
    2. Recommend. A short list ranked by the expected saving, each item with its current value, the recommended value, the evidence and a one-line reason. Items that would make little or no difference are listed separately as "no change needed" instead of being pushed on you.
    3. Apply, item by item. You see the before and after for each item first, and only the items you say yes to are written. Each item is confirmed in a Claude Code confirmation dialog, and the previous file is backed up first. Each change can be reverted later.
    4. Re-check weekly. From one week after install, the advisor runs the same analysis again when you start a session and, if something changed, offers a card the next time you open one.

    →Run the full flow (analyze, recommend, approve each item, apply, revert):

    /token-stamina:advisor

    Or just look, without changing anything: /ts-advisor prints the same analysis and recommendations as a read-only report (--days N to change the window, --json for raw output).

    Reads
    Only the session transcripts already on this device, under ~/.claude/projects. The last 30 days, this device only.
    Sends
    Nothing. No network request, no telemetry.
    Models
    None. The analysis is deterministic arithmetic and every sentence comes from fixed templates filled with numbers, so the same records give the same screen.
    Changes
    A change is written only for an item you approve yourself, one by one, in a Claude Code confirmation dialog that shows file key: before -> after. Your answer to Claude in the chat is not enough, and in a non-interactive (-p) run nothing is written. A backup copy of the file is saved first (settings.json.bak-token-stamina-<time> next to settings.json; the Token Stamina config is backed up inside its own folder). Each change can be reverted, and only while the value is still the one the advisor set. The weekly check can apply by itself only if you list a rule in advisorAutoApply (off by default) and only to Token Stamina's own config, never to settings.json.
    Weekly re-check
    It runs in the background when a Claude Code session starts or resumes, from one week after install, and only reads local records. There is no operating-system scheduled task, so if you don't open Claude Code it doesn't run, and it catches up the next time you do. Set "advisor": false in the config to turn it off.
    Money
    Shown as the API list-price equivalent, an estimate. On a subscription you are not billed this; your plan limit fills in the same proportion.
    Limit
    A transcript over 4 MiB can't be read by the plugin, so it is counted and left out. Those are mostly long main sessions, so the main-session figures are a lower bound, and the screen says so.

    Layout, wording and prices follow the real screen; the numbers are made up.

    What the cost terms mean 
    cache read: re-reading the stored conversation on every call (cheap per token).
cache write: storing new context for reuse (costs more than a normal input token).
output: the text and code the model writes (the dearest per token).
context: everything sent with a call: tools, system text and the conversation.

    06What runs on your machine

    Reads
    The usage numbers Claude Code reports for the session, and your session transcripts under ~/.claude/projects, to add up usage and build the handoff note, and the subagent files Claude Code keeps there, to count what is running.
    Writes
    Only to ~/.claude/token-stamina/, and to your settings file during setup or an approved Usage Advisor change, if you agree (the optional board preview can also update its own config file when you approve a setting there). Handoff notes keep short clips of your recent requests; after 7 days their text is emptied. Delete the folder to remove them sooner.
    Never
    It makes no network requests of its own (the optional board preview, if you set it up, asks Claude to write to your own private Artifact), sends no telemetry, calls no model and starts no commands. Hint lines and handoff notes it adds to the conversation are sent to the model like the rest of your conversation.

    The full file-by-file list is in the README. To remove everything, uninstall the plugin and delete that folder.
