Make your weekly limit last until the reset.

Usage meters tell you where you stand. Token Stamina acts on it. This Claude Code plugin compares how much of your weekly and 5-hour limits you've used with how much of each window has passed. When you're well ahead of pace, it moves subagents to cheaper models by itself. When a long conversation reaches the end of a task, it suggests a compact, with an estimate of what it saves when it can make one, and saves a handoff note first so you don't lose your place.

claude · ~/work/api
> refactor the billing client and add tests ✓ 4 files edited · committed "split billing client"
~/work/api main │7d 62%·today 5.4% ·reset Mon 15:00·ctx 41%

    Always on, at any grade: a handoff note saved at the end of each turn and restored after a compact or clear, and a /compact suggestion when the conversation gets long.

    01What it does

    1. Subagent model. auto While the grade is red, a subagent call with no model set goes to Haiku if the task looks simple and to Sonnet otherwise. If the call names a model, is a fork, or looks like review or design work, it's left alone. You can change this to suggestions only, or turn it off.
    2. Handoff note. auto At the end of each turn it saves the last few requests, commits, edited files and to-dos, and adds them to the new conversation after you compact or clear. The note is put together from your transcript; no model writes it. You can compact early and not have to explain again where you were.
    3. Compact suggestion. suggestion Once the conversation is large and you've just finished something (a commit, an edit, an answer), it suggests /compact with the commit subjects filled in. If the conversation is much larger than that, it suggests a new session instead.
    4. Auto-compact point. set once Setup can lower Claude Code's automatic compact point, so a long session doesn't keep re-reading a very large context on every call.
    5. Grade change. once When the grade changes, Claude gets one short line and tells you, in your language. Nothing is added while the grade stays the same.

    It doesn't change your main conversation's model or block requests. It doesn't compact by itself either: Claude Code doesn't let plugins run /compact. /token-stamina:audit lists what gets loaded into every conversation, such as CLAUDE.md files, plugins and MCP servers you never use. It only reports and doesn't change anything.

    02How the grade works

    The status line shows the numbers Claude Code already passes to it, plus the grade.

    ~/work/api  main  │  7d 84% · today 5.3% ● · reset Mon 15:00 · ctx 41%
    7d 84%
    weekly limit used, as reported by Claude Code
    today 5.3%
    what you can use per day from now and still make it to the reset
    ●
    grade: green, yellow or red
    reset Mon 15:00
    when the weekly window resets
    ctx 41%
    how full this conversation is

    60% used with a day left is fine. 60% used on day two isn't. So the grade compares usage with time. Green if usage is at or below the share of the window that's gone. Yellow if it's up to 10 points over. Red if it's more than 10 points over, or at 90% or more at any point. The weekly and 5-hour windows are graded separately and you see the worse one.

    03Install

    1In a terminal:

    claude plugin marketplace add token-stamina/token-stamina
claude plugin install token-stamina@token-stamina

    2Then in Claude Code:

    /token-stamina:setup

    A plugin can't set the status line by itself, so setup asks before it changes ~/.claude/settings.json. If you already have a status line, it can keep yours and add to it.

    Or do step 1 inside Claude Code

    Run these one at a time, then run setup:

    /plugin marketplace add token-stamina/token-stamina
    /plugin install token-stamina@token-stamina

    04What runs on your machine

    Reads
    The usage numbers Claude Code passes to the status line, and your session transcripts under ~/.claude/projects, to add up usage and build the handoff note.
    Writes
    Only to ~/.claude/token-stamina/, and to your settings file during setup if you agree. Handoff notes are deleted after seven days.
    Never
    Its scripts send no telemetry and call no model. Their only network request is the update check: once a day at most, one download of the published version number from GitHub, so it can tell you when a new version is out ("updateCheck": false turns it off). Two commands it can start may go online: claude plugin list during an audit, and a status line command you've asked it to wrap. Hint lines and handoff notes it adds to the conversation are sent to the model like the rest of your conversation.

    The full file-by-file list is in the README. To remove everything, uninstall the plugin and delete that folder.
