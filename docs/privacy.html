Privacy Policy

Last updated: 2026-11-01 (plugin version 0.6.0). Token Stamina is an independent, community-made plugin for Claude Code. It is not affiliated with Anthropic.

Token Stamina runs on your own machine as a hooks module and commands inside Claude Code. It has no server and no account. It makes no network requests, collects no telemetry, makes no model calls of its own, starts no other programs and does not profile you. This page lists what it reads, what it writes and what can leave your machine.

What it reads
Only on your machine: the usage numbers Claude Code reports for the session (weekly and 5-hour limits, reset times, context size); your session transcripts under ~/.claude/projects (usage per model, what the last turn did, MCP and skill usage counts) and the subagent metadata files Claude Code keeps there (description, agent type, model, finished flag) to count running subagents and active sessions; the text of each prompt, to detect its language and for the handoff note; and, for a subagent call, its description and prompt and the model: line of the agent definition, to choose a model (not stored). At startup it reads ~/.claude/settings.json to see whether the status line entry of an older version is still there. The /ts-audit command also counts the characters of your always-loaded files (CLAUDE.md, MEMORY.md), lists enabled and installed plugins, and reads MCP server names (no keys or values). Transcript files over 4 MiB are skipped.
What it writes
Its own files go under ~/.claude/token-stamina/ (or the folder in TOKEN_STAMINA_HOME): state.json (the last usage reading); events.jsonl (session ids, token counts, which hint fired, subagent model decisions; rotated at 3 MiB, and old rotated files are kept); per-session bookkeeping that keeps the last 50 sessions (nudge.json, boundary.json, topic-gate.json with the working folder and prompt times, lang.json); explicit-downgrade.json; audit-cache.json (transcript paths and MCP and skill names); a one-time marker legacy-statusline.json; and the handoff/ folder. config.json is written only when you run /token-stamina:setup or /token-stamina:autocompact and agree. Outside that folder, those two commands can change ~/.claude/settings.json (removing the old status line entry, the auto-compact window) and optionally ~/.claude/keybindings.json, only after showing the change and getting your yes; a backup of settings.json is saved first.
Handoff notes
To survive a /compact or /clear, it saves a short note in ~/.claude/token-stamina/handoff/: the working folder path and session id, up to the last three requests (each clipped to 200 characters), commit subjects, edited file paths and to-do items. A side file keeps up to 40 commit subjects and file paths, and the last few turns (your text and Claude's reply, each clipped to 140 characters; three by default, "clearRecentTurns": 0 keeps none), which are shown on screen after a clear and not sent to the model. When asked before a compact or clear, Claude may also write its own note there. Notes are not deleted automatically in this version; delete the handoff/ folder to remove them. Set "handoff": false in ~/.claude/token-stamina/config.json to stop writing and restoring notes (existing notes stay until you delete them). Restored notes and hint lines are added to the conversation, so Claude Code sends them to the model like any other context.
Network
None. The plugin makes no network requests. If you upgraded from 0.5.x and have not run /token-stamina:setup yet, the old status line entry in your settings still runs your own status line command, if it wrapped one; Token Stamina itself adds nothing to it.
What it does not do
No telemetry, no analytics, no advertising, no sale or sharing of data, no calls to any language model, and no profiling. It does not send your transcripts, prompts or files anywhere.
Removing your data
Uninstall the plugin, delete ~/.claude/token-stamina/, and remove any leftover Token Stamina statusLine and env.CLAUDE_CODE_AUTO_COMPACT_WINDOW from ~/.claude/settings.json (or restore the settings.json.bak-token-stamina-* backup).
Contact
Questions or concerns: open an issue on GitHub. Changes to this policy are published on this page and in the repository history.
